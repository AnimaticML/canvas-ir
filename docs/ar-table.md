# AR Table Lab — демо 1

Отдельная экспериментальная страница `ar.html` развивает стек существующего
`babylon.html`: Babylon.js, физика Havok и поверхность CanvasIR через
`@canvas-ir/babylon` (`World`, `Surface`, `Components`). Новый графический или
физический движок не вводится. Исходная страница 3D остаётся доступной; ссылка на
AR-дeмо есть в её верхней панели.

## Запуск

```sh
bun install --frozen-lockfile
bun run --cwd packages/playground build
python -m http.server 8080 --directory packages/playground/dist
```

На компьютере: `http://localhost:8080/ar.html`. Для камеры смартфона нужен HTTPS.
Существующий workflow GitHub Pages публикует весь `dist`, включая `ar.html`,
OpenCV, WASM MediaPipe и Havok. После публикации страница будет доступна по
`https://animaticml.github.io/canvas-ir/ar.html`. Само добавление кода не публикует
страницу: нужен обычный merge/deploy репозитория.

Для AR используйте собранную страницу: обычный `playground dev` не копирует
`ar-vendor`. Сервер разработки — только способ раздать статические файлы; в демо
нет backend, комнаты, сохранения сессий или передачи видео. OpenCV 4.11.0 и
MediaPipe Tasks Vision 0.10.32 закреплены зависимостями. Модель версии float16/1 скачивается с `storage.googleapis.com` во время сборки,
проверяется по SHA-256 и публикуется рядом с приложением. В браузере OpenCV,
MediaPipe, WASM и модель загружаются с того же статического сайта; обработка
кадров выполняется на устройстве. Сборка кеширует модель в `.ar-cache`
(не в Git); для сборки без доступа к Google можно передать
`AR_HAND_MODEL_PATH=/путь/hand_landmarker.task`. Контрольная сумма проверяется
и для локального файла.

## Подготовка и привязка

1. Откройте «Подготовить маркеры». Демо генерирует настоящие `DICT_4X4_50`, ID
   0/1/2, тем же OpenCV, который их распознаёт. Можно использовать и другие
   уникальные ID этого словаря.
2. Перерисуйте 6×6 ячеек (4×4 данные + рамка шириной в ячейку) на бумаге в клетку,
   полностью закрасив чёрные клетки; оставьте белое поле. Или распечатайте при
   масштабе 100%. Измерьте внешнюю сторону чёрного квадрата и укажите её в см.
   Все маркеры должны иметь одинаковый размер и разные ID.
3. Положите маркеры на одну плоскость и включите заднюю камеру. Сначала покажите
   несколько маркеров вместе примерно секунду. Первый распознанный маркер с
   наименьшим ID задаёт начало координат и ориентацию поверхности 60×40 см.
4. Новый ID должен быть виден с уже известным. Приложение накапливает 12
   согласованных наблюдений положения на столе и добавляет маркер в общую карту.
   Можно собирать карту по цепочке перекрывающихся наблюдений.
5. Нажмите «Зафиксировать карту». После этого перемещайте телефон. Бумажные
   маркеры должны оставаться неподвижными. Добавление новых маркеров можно
   включить снова; для изменения раскладки используйте «Новая привязка».

Позу оценивают по углам доступных известных маркеров. Проверка согласованности
отбрасывает противоречивые маркеры, затем `solvePnP` уточняет позу по всем углам
согласованных наблюдений. Для движения применяется сглаживание трансляции и
кватерниона с уменьшающимся при движении временем фильтра. Режим «Выкл.» позволяет
оценить влияние фильтра на дрожание и отзывчивость.

Если все известные маркеры потеряны, виртуальная сцена скрывается: замороженная
проекция на движущемся видеопотоке вводила бы в заблуждение. Карта остаётся в
памяти, и любой известный маркер восстанавливает прежнюю систему координат.
Неизвестный ID при потере привязки не создаёт новое начало координат.

Для сравнения выберите ручную привязку. Выберите четыре угла реального
прямоугольника **60×40 см**: дальний левый, дальний правый, ближний правый,
ближний левый. Телефон в этом режиме должен быть неподвижным. Непрямоугольный
четырёхугольник или ошибочный порядок углов могут быть отклонены.

## Руки и взаимодействия

Включите MediaPipe. Отображаются 21 точка кисти и скелет, кончик указательного
пальца и его проекция на стол. Поддерживается одна кисть.

- **Луч → стол:** пересечение луча кончика пальца с Y=0. Это режим 2D, он не
  измеряет высоту и не включает 3D-кнопку или захват. Высота отображается как `2D`.
- **3D:** `solvePnP` по метрической геометрии `worldLandmarks` MediaPipe и 21
  соответствующей точке изображения. Результат переводится из координат камеры
  в координаты стола. Некорректные решения отбрасываются по ошибке проекции,
  правдоподобию размеров кисти и высоте.
- **3D с касанием:** в режиме 3D положите указательный палец на стол и нажмите
  «Калибровать касанием». Удерживайте его неподвижно около секунды. Медианная
  высота стабильной серии задаёт смещение Y. Коррекция действует в координатах
  стола, поэтому не привязана к исходному положению телефона. После изменения
  ракурса проверяйте её и при необходимости повторяйте касание.

Зелёная кнопка нажимается указательным пальцем в пределах её площади и допуска
по высоте; требуется два последовательных кадра, а отпускание имеет отдельный
порог. Проекционный режим не выдаёт ложное «измеренное касание».

Сблизьте большой и указательный пальцы около кубика или карты. Захват происходит
по переходу в pinch; у захвата и отпускания разные пороги. Предмет следует за
серединой между пальцами, сохраняя смещение точки захвата. Ориентацию задаёт базис
ладони (запястье и основания пальцев), начальный поворот предмета сохраняется.
Удерживаемое тело становится `ANIMATED` и управляется `setTargetTransform` Havok;
при отпускании возвращается `DYNAMIC`. Краткая потеря кисти удерживает предмет
до 600 мс; затем он отпускается. Потеря самого стола немедленно прекращает
взаимодействие. Упавшие за край предметы возвращаются на стол.

Остановка камеры, уход со страницы или её скрытие освобождают видеотреки.
Изменение размера кадра, угла обзора, размера маркера или способа привязки
сбрасывает калибровку. Карта не сохраняется после перезагрузки.

## Протокол проверки на смартфоне

Синтетические проверки подтверждают правильность геометрии и программного
взаимодействия; они **не подтверждают** точность руки на реальном устройстве.

1. Неподвижная камера: 10–20 секунд наблюдайте совпадение сетки с реальными
   контрольными точками. Зафиксируйте дрожание, ошибки проекции и частоту трекинга.
2. Сдвиг/поворот/наклон телефона: проверяйте совпадение на ближнем и дальнем краях
   стола. Сравните фильтр выкл./55/110 мс и субъективную задержку.
3. Маркеры: сравните распечатанные и нарисованные ручкой; перекройте по одному,
   затем все маркеры, верните в кадр только маркер, который не был первым.
4. Касание: откалибруйтесь один раз, сделайте 20 нажатий на кнопку. Отдельно
   запишите пропуски и ложные нажатия при проведении пальцем над ней.
5. Высота: приготовьте опоры 0/2/5/10 см. В раскрывающемся блоке диагностики
   выберите реальную высоту и снимите двухсекундный замер. Повторите под новым
   ракурсом без перекалибровки, затем с повторным касанием.
6. Захват: 10 раз поднимите, перенесите, поверните и отпустите кубик, затем карту.
   Проверьте перекрытие маркеров рукой, краткую потерю кисти и отпускание.
7. Введите удобство 1–5 и наблюдения, скачайте JSON. Отчёт содержит исходные
   выборки высот, среднее, смещение от эталона, стандартное отклонение, параметры
   камеры и карты, счётчики действий и заметки.

Диагностика RMS позы вычисляется в окне 2 с и включает намеренное движение камеры;
для измерения дрожания держите телефон неподвижно. Время обработки и возраст
результата не включают неизвестную задержку сенсора. Процент качества — эвристика
из ошибки PnP, а не вероятность корректного трекинга.

## Ограничения исследования

Параметры камеры приблизительны: fx/fy оцениваются по горизонтальному углу обзора,
главная точка — центр кадра, дисторсия не моделируется. Ползунок угла обзора
помогает экспериментировать, но не заменяет калибровку камеры. Масштаб кисти
MediaPipe — оценка модели; касание исправляет смещение высоты, но не все ошибки
масштаба, формы кисти, дисторсии или ракурса. Различение 2 см и перенос калибровки
между ракурсами требуют натурной проверки. Дрожание/ошибка при рисунках от руки
зависят от заполнения ячеек, размеров, освещения и качества изображения.

Обработка сейчас выполняется на основном потоке, без очереди кадров, с верхним
пределом 15 проходов/с и шириной анализа до 800 px. На слабых телефонах MediaPipe
и OpenCV могут снижать частоту и отзывчивость; измеряйте её на целевом устройстве.
Нет визуальной инерциальной одометрии, маски окклюзии рукой, WebXR/ARCore,
синхронизации или сохранения карты. Рука рисуется поверх сцены диагностическим
скелетом, но не скрывает виртуальные объекты как физический объект.

## Автоматические проверки

```sh
bun test packages/playground/test/ar.test.ts
bun run typecheck
bun run --cwd packages/playground build
# Установить Chromium средствами Playwright либо указать существующий бинарник:
CHROMIUM_PATH=/usr/bin/chromium bun packages/playground/scripts/test-ar-browser.ts
```

Геометрические тесты используют настоящий OpenCV: стандартные коды, наклонная
проекция, произвольная раскладка, восстановление по другому ID, неизменность
замороженной карты, геометрическая реконструкция высоты. Браузерная проверка
подаёт синтетическое Y4M-видео через `getUserMedia` Chromium, проверяет совпадение
матриц OpenCV/Babylon, ручную привязку, физические действия Havok, загрузку
MediaPipe и обработку кадра без руки, мобильную вёрстку и освобождение камеры.
Она не заменяет проверку распознавания настоящей руки.
